Large Language Models & Transformers

A comprehensive guide to understanding how modern AI systems work, from architecture to training.

What are Large Language Models?

Large Language Models (LLMs) are AI systems trained on massive amounts of text data to understand and generate human-like text. They power modern AI applications like ChatGPT, Claude, and many others.

Key Characteristics

  • Scale: Billions to trillions of parameters
  • Pre-training: Learn from vast internet-scale datasets
  • Transfer Learning: Apply knowledge to new tasks
  • Few-Shot Learning: Learn from minimal examples

The Transformer Architecture

Introduced in "Attention Is All You Need" (2017), transformers replaced recurrent networks with parallel processing, enabling the creation of much larger and more powerful models.

Self-Attention

Each word attends to all other words in context, allowing the model to understand relationships across the entire input.

Parallel Processing

Process entire sequences simultaneously instead of one token at a time, dramatically improving training speed.

Positional Encoding

Maintain word order information through mathematical position embeddings added to input vectors.

Layer Stacking

Deep networks with many transformer layers learn hierarchical patterns from simple to complex.

Pre-training Phase

The foundation of all modern LLMs - training on massive text corpora to learn language patterns, knowledge, and reasoning.

Training Objective

Next-token prediction: Given a sequence of tokens, predict the next token. This simple objective teaches models grammar, facts, reasoning, and more.

Training Data Sources

  • Web pages (Common Crawl, filtered internet)
  • Books and publications
  • Code repositories (GitHub, etc.)
  • Academic papers and research
  • Wikipedia and curated high-quality sources

Scale Example: GPT-3

  • 300 billion tokens of training data
  • 175 billion parameters in the model
  • $4.6 million in compute costs
  • Several weeks of training on thousands of GPUs

Post-training Phase

Transforming raw language models into helpful, harmless, and honest AI assistants through alignment techniques.

Supervised Fine-Tuning (SFT)

Train on high-quality demonstrations of desired behavior, teaching the model to follow instructions and respond helpfully.

RLHF

Reinforcement Learning from Human Feedback - optimize the model based on human preferences using reward models.

Why Post-training Matters

Pre-trained models only complete text - they don't follow instructions, can generate harmful content, and aren't aligned with human values. Post-training fixes all of these issues.

Key Concepts

Tokens

Text is broken into tokens (words, subwords, or characters) before processing.

"Hello, world!" → ["Hello", ",", " world", "!"]

Context Window

Maximum number of tokens the model can process at once:

  • GPT-3: 4,096 tokens (~3,000 words)
  • GPT-4: 128,000 tokens (~96,000 words)
  • Claude 3: 200,000 tokens (~150,000 words)

Temperature

Controls randomness in generation:

  • 0.0: Deterministic, always picks most likely token
  • 0.7: Balanced creativity and coherence
  • 1.0+: More creative but less predictable

Model Context Protocol & Agentkits

Building AI agents that can actually interact with the world through standardized protocols and tools.

What is the Model Context Protocol?

MCP is a standardized protocol that allows AI models to connect to and interact with external data sources, tools, and services. Think of it as HTTP for AI agents - a universal way for LLMs to communicate with tools.

Why MCP Matters

Connect to Tools

Integrate with APIs, databases, and services seamlessly

Access Data

Retrieve and process information from various data sources

Take Actions

Execute tasks and workflows in external systems

Maintain Context

Keep track of state across interactions and sessions

Core Components

Resources

Data or content that AI models can access:

  • Files and documents
  • Database records
  • API responses
  • Web pages and content
  • Real-time data streams

Tools

Functions that AI models can invoke to perform actions:

  • Query databases
  • Call external APIs
  • Execute code
  • Modify files
  • Send notifications

Prompts

Reusable templates that provide context and structure:

  • Pre-configured conversation starters
  • System prompts with embedded context
  • Workflow templates
  • Role definitions

Architecture

MCP uses a client-server architecture where AI applications connect to servers that provide resources and tools.

Client Application (Host)
↕
LLM (AI Model)
↕
MCP Client
↕

Data Sources / APIs

Protocol Basics

MCP is built on JSON-RPC 2.0, making it simple, debuggable, and language-agnostic.

Example Tool Call

{
  "jsonrpc": "2.0",
  "id": "1",
  "method": "tools/call",
  "params": {
    "name": "search_database",
    "arguments": {
      "query": "AI papers",
      "limit": 10
    }
  }
}

Building Your First MCP Server

Installation

# TypeScript/JavaScript
npm install @modelcontextprotocol/sdk

# Python
pip install mcp

Basic Server Example

import { Server } from "@modelcontextprotocol/sdk";

const server = new Server({
  name: "my-server",
  version: "1.0.0"
});

// Define a tool
server.setRequestHandler("tools/list", async () => ({
  tools: [{
    name: "echo",
    description: "Echoes back the input",
    inputSchema: {
      type: "object",
      properties: {
        message: { type: "string" }
      }
    }
  }]
}));

// Start server
await server.connect(transport);
